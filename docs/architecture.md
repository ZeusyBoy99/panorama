# Architecture

```text
RaceEngine → MockProvider ─┐
Validated replay → ReplayProvider ─┼→ SessionController → race store → selectors → timing / details / events
Future live adapter ──────────────┘                         └→ map resolver → local SVG renderer
                                                      preferences / last-known cache
```

Providers implement `TimingProvider`: connect/disconnect, snapshot/status subscriptions with cleanup, capabilities, and a full snapshot for resynchronisation. Playback controls are optional; mock fault injection and replay seeking stay outside the minimal future-live contract.

`SessionController` validates unknown input using Zod, checks session/stream/sequence identity, rejects duplicates and old messages, deduplicates bounded events, timestamps receipt, replaces race state, records up to 60 snapshots and persists a bounded last-known snapshot every two wall seconds. A generation token and unsubscribe-before-disconnect prevent old providers from mutating a new source. Retired stream identities cannot return; the bounded set tracks the most recent 32. Resynchronisation only occurs while connected, so visibility changes cannot defeat an injected transport outage.

`useRace` owns accepted transport data, monotonic receipt time, connection/playback status, cache/source state and validation diagnostics. `useUI` independently owns interface style (friendly or Hacker UI), theme, density, reduced motion, favourites, search, selection and dialog state. `useRuntime` selects the provider. Pure formatting/classification selectors use source positions; map estimates never rerank entries. A selected entry is identified by stable ID and mirrored to a car query parameter.

## Clocks

- Engine elapsed milliseconds advance in deterministic 50 ms ticks. Fractional advance calls accumulate a remainder. Hashed seed/index/lap variation never depends on browser frames.
- Source timestamps use the configured fictional event epoch plus engine elapsed time. They are not the user's wall time.
- Confirmed observations carry elapsed-source-clock timestamps, separately for each car. Heartbeats do not refresh an old anchor or silent car.
- Receipt timestamp is local wall time for persistence/freshness notices. Animation uses `performance.now()` relative to the accepted receipt anchor.
- Replay cursor provides a continuous replay elapsed clock while retaining each record's original source timestamp and car observation timestamps. Playback cannot fabricate new laps/events/anchors between records.
- Paused playback freezes motion and carries its own label. Outage is 15 real seconds at every playback speed. Offline browser status remains independent; local simulation works offline.

## Simulator and classification

The opening checkpoint is generated by advancing the actual engine until the leader completes lap 42, then another 12 seconds. Finish uses lap 160 plus 115 seconds. Seeded checkpoint states are reused only as immutable deep copies. Each car tracks its own lap plan, sector/crossing histories, pit traversal, current driver, stints and status. All crossed boundaries are processed at within-tick timestamps.

Green target lap duration is `126000 + 180 * fixtureIndex` ms with up to ±600 ms hashed variation. The piecewise time/distance profile integrates the three demo sectors exactly. Grid release is spaced by 650 ms. Classification uses simulator scoring distance, independently of map presentation. Retired cars stay behind active cars, retaining distance order. After the winner completes 161, each active car finishes at its next timing line; final ties on completed laps use finish timestamp. This is a demonstration scoring policy, not the full race regulations.

Second gaps use the most recent common timing-point/lap history. An incompatible/negative comparison is unknown until another comparable crossing. A full scoring-distance deficit of at least one lap uses a lap tag; merely differing completed-lap counters near the timing line does not establish a whole-lap deficit.

## Map

The locally bundled OSM circuit geometry exports ordered coordinates, sourced pit road and demo anchors. See geometry-attribution.md. Geometry creates an arc-length lookup for coordinate/orientation resolution; pit progress uses its own lookup. The simulator's position profile exposes timestamped samples. Sector/lap projections remove continuous position and pit progress before publication. Classification strips all position anchors.

The resolver imports only transport types, speed-profile functions, and geometric demo anchors. Sector estimates use the last confirmed boundary and a valid previous duration. Lap estimates use a lower-confidence piecewise lap model. At expected duration, motion clamps to the boundary; after a grace period confidence reduces, then positions become unavailable. No inferred crossing becomes measured data. Unknown pit/retirement locations and sparse timing under caution/red flags move to a non-positional status area.

SVG markers update locally through requestAnimationFrame; React and global race state stay at 2 wall Hz. Wrapped progress interpolates forward, while large discontinuities reset. Selection updates styling and drawing order without restarting the snapshot interpolation interval. Car bodies remain on the track or pit lookup; close number labels alternate lateral offsets with connector lines. Selected markers render above others. Reduced motion disables interpolation, using a one-second freshness redraw. Hidden-tab animation frames are cancelled. Visible restoration obtains a full snapshot when connected. Very long suspended wall intervals cap simulator catch-up at two seconds per pulse; no uninterrupted background execution is promised.

## Persistence and PWA

Versioned preference and snapshot keys use localStorage with safe error handling. Cache identity includes schema/provider/session and original timestamps. Records are exported locally rather than silently stored without bounds. Manifest/icon assets, app shell, track code and compact bundled replay are precached. Timing transport has no caching rule. Native dialog focus management, text-safe React rendering, reduced motion, install feature detection and optional wake lock complete the browser layer.
